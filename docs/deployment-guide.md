## Shape of a deployment

One binary, one long-running server, one port (**default 49374**). Agents connect over MCP
(stdio or HTTP) and the hook ingress. Runs either **local (loopback)** or on a **homelab box**
(LAN/VPN/cloud) with bearer-token auth. Data lives in `<data_dir>` (`/data` in Docker, platform
data dir natively, or `AI_MEMORY_DATA_DIR`): `db/memory.sqlite` + the markdown `wiki/`.

## Distribution channels

| Channel | Command / artifact | Notes |
|---|---|---|
| **Docker (recommended)** | `akitaonrails/ai-memory:latest` + `bin/ai-memory` wrapper | Multi-arch `linux/amd64` + `linux/arm64` (no emulation on Apple Silicon/ARM) |
| **Arch AUR** | `yay -S ai-memory-bin` (prebuilt) / `yay -S ai-memory` (source) | Installs `/usr/bin/ai-memory` + systemd system/user units |
| **macOS / Windows** | `ai-memory-macos-<arch>.tar.gz` / `ai-memory-windows-x86_64.zip` | From GitHub Releases; no toolchain needed |
| **cargo install** | `cargo install --git …/ai-memory --tag vX.Y.Z` | Self-contained build (bundled SQLite + vendored libgit2) |
| **Client-only hooks** | `curl -sSL …/scripts/install-hooks.sh \| bash -s -- --agent claude-code` | For machines that are only *clients* of a remote server |

After install: `ai-memory install-mcp --client <c> --apply` and (where supported)
`ai-memory install-hooks --agent <a> --apply`.

## Docker

`docker/Dockerfile` is multi-stage:
- **builder** — `rust:1.95-slim-bookworm`, BuildKit cache mounts, `TAILWIND_SKIP=1 cargo build --release -p ai-memory-cli`.
- **runtime-base** — `debian:bookworm-slim`, non-root `ai-memory` user (uid 1000, home `/data`),
  bundled `hooks/` at `/usr/local/share/ai-memory/hooks`, `EXPOSE 49374`, HEALTHCHECK
  `ai-memory status`, `ENTRYPOINT ["ai-memory"]`,
  `CMD ["serve","--transport","http","--bind","0.0.0.0:49374","--enable-web"]`.
- **runtime-prebuilt-{amd64,arm64}** — copy the prebuilt release binary (used by release + CI;
  **no Rust recompile in Docker**).
- **runtime-source** — from-source build (default full-build target).

Default env in the image: `AI_MEMORY_DATA_DIR=/data`,
`AI_MEMORY_ALLOWED_HOSTS="localhost,127.0.0.1,::1,host.docker.internal"`.

**Compose files** (`docker/`):
- `docker-compose.yml` — dev/local (builds `ai-memory:local`, loopback `127.0.0.1:49374`, named volume).
- `docker-compose.prod.yml.example` + `.env.production.example` — homelab prod templates (copy + edit).
- `compose.tls.caddy.yml` — ai-memory + Caddy TLS-terminating reverse proxy.
- `compose.tls.cloudflared.yml` — ai-memory + Cloudflare Tunnel (outbound-only, edge TLS, no exposed ports).

## Native Linux (systemd)

AUR packages install: `/usr/bin/ai-memory`, hooks under `/usr/share/ai-memory/hooks/`, and:
- `packaging/systemd/ai-memory.service` — system service (`User=ai-memory`,
  state `/var/lib/ai-memory`, config `/etc/ai-memory/config.toml`; hardened:
  NoNewPrivileges / PrivateTmp / ProtectHome / ProtectSystem=strict / ReadWritePaths).
- `packaging/systemd/ai-memory-user.service` — per-user service.
- `packaging/sysusers/ai-memory.conf` (creates the system user),
  `packaging/tmpfiles/ai-memory.conf` (creates `/var/lib/ai-memory`),
  `packaging/env/ai-memory.env` (secrets file, root-readable `0640`).

Validate packaging without mutating the host: `scripts/check-native-packaging.sh` (run in CI).

## Auth & network safety

- **Any non-loopback bind requires** a bearer token (`ai-memory generate-auth-token`) **and**
  `AI_MEMORY_ALLOWED_HOSTS`.
- TLS is terminated by a reverse proxy — Caddy or Cloudflare Tunnel compose files above; see
  [`https-via-proxy.md`](./https-via-proxy.md).
- Shared servers can opt into [`[auto_scope]` modes](./auto-scope.md) for per-user / session-aware
  project routing.

## Homelab push-deploy

`bin/deploy` builds → `docker push` → SSHes to the homelab box → `docker compose pull/down/up -d`.
Reads `bin/deploy.env` (gitignored; template `bin/deploy.env.example`).

## Releasing

Cutting a release (`bin/release <version>`, operator-driven — does **not** push):
1. Validates semver, runs fmt/clippy/test gates (+ deny/audit warn-only).
2. Bumps `Cargo.toml` version + intra-crate dep versions, syncs `Cargo.lock`.
3. Moves CHANGELOG `[Unreleased]` → `[X.Y.Z]`, commits `release: vX.Y.Z`, creates an annotated tag.

Pushing the `v*.*.*` tag triggers `.github/workflows/release.yml`: validates tag==Cargo version,
builds Linux/macOS/Windows tarballs (bundling binary + hooks + packaging assets + docs, with
`.sha256`), builds+pushes multi-arch Docker images (reusing prebuilt binaries), composes the
`latest`+`<version>` manifest, creates the GitHub Release, and regenerates+pushes both AUR
PKGBUILDs. `check-secrets` makes Docker/AUR publish fork-friendly (warn+skip if secrets absent).

## LLM tiers (optional, layered via env)

1. **Zero-LLM default** — FTS5 + rule-based summaries, $0.
2. **LLM consolidation** — set `AI_MEMORY_LLM_PROVIDER` (+ key/OAuth): anthropic, anthropic-oauth,
   openai, openai-oauth, copilot, gemini, opencode, openai-compat.
3. **Hybrid retrieval embeddings** — set `AI_MEMORY_EMBEDDING_PROVIDER`: openai / voyage / google.
