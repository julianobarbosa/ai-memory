# Data Models — ai-memory

> Generated by BMAD `document-project` (deep scan, 2026-07-28). Derived from
> `crates/ai-memory-store/migrations/V01..V35` and `crates/ai-memory-core`.
> **Backend: a single SQLite file** at `<data_dir>/db/memory.sqlite` (WAL mode,
> `synchronous=NORMAL`, `busy_timeout=5000ms`, foreign keys ON at runtime). There is **no
> external vector database** — semantic search rides on SQLite (FTS5 + an embeddings blob table).

## Migration framework

- **Runner:** `refinery` (via `migrations.rs`) over embedded SQL files `V01__init.sql` …
  `V35__session_end_observation_watermark.sql` — **35 migrations**, run at `Store::open`.
- Migrations run with **FK enforcement OFF** (refinery wraps each in a transaction); FKs are
  re-enabled for runtime.
- **On-disk wiki** has a *separate*, filesystem-only migration framework in `ai-memory-wiki`
  (`WikiMigration` trait) — currently empty by design (the UUID-per-project layout is native).

## Core domain model (from `ai-memory-core`)

The universal identity coordinate on every content table is the **3-tuple
`(WorkspaceId, ProjectId, PagePath)`**. All IDs are UUID-v7 newtypes (time-ordered), stored as
16-byte BLOBs.

### A "memory" is a `Page`
One markdown file under `<wiki_root>/<ws>/<proj>/<page-path>`, mirrored as a row in `pages`.

| Field | Meaning |
|---|---|
| `title`, `body` | Rendered content (H1 of body → title) |
| `body_sha256` | Content address — identical hash ⇒ no-op write |
| `tier` | `Working` → `Episodic` → `Semantic` → `Procedural` (models lifetime) |
| `frontmatter` | JSON column (tags, canonical/active/superseded markers, etc.) |
| `pinned` | Exempt from decay sweep **and** from auto-improve rewrite |
| `is_latest`, `supersedes` | In-place versioning: a new write flips the prior row's `is_latest` to false and links back via `supersedes` |
| `created_at`, `updated_at`, `author_id?` | Timestamps + optional attribution |

**Lifecycle / supersession:** pages are versioned *in place*. A changed body creates a new
`is_latest=true` row pointing `supersedes` at the previous row (now `is_latest=false`). A
unique index enforces exactly one latest per `(workspace, project, path)`. Identical body is a
no-op. Tiers model decay lifetime; `pinned` pages never decay.

### Other core records
- **`Observation`** — raw, never-user-facing capture events (one per lifecycle hook event);
  feed the consolidation pipeline. `ObservationKind` mirrors the hook vocabulary.
- **`Session`** — an agent session; `agent_kind` is CHECK-constrained to the known `AgentKind`
  set (kept in sync via migrations as new agents are added).
- **`Handoff`** — first-class cross-agent "where we are" snapshot with an
  `Open → Accepted → Expired` state machine.
- **`User`** — multi-user attribution (added V14–V16); token auth in `store::users`.

## Search & retrieval data

- **FTS5** (`pages_fts`, observations FTS): keyword candidates; user queries sanitized via
  `prepare_fts5_query` into a safe MATCH expression. Diacritic-insensitive (V12).
- **Embeddings** (`page_embeddings`): optional vector RRF layer. Vectors are unit-normalized
  `Vec<f32>` packed to bytes (`f32_vec_to_bytes`). `(provider, model, dim)` is checked at
  startup — a mismatch refuses rather than silently returning garbage. Default dims:
  `text-embedding-3-small`=1536, Voyage=1024, Gemini=768.
- **Authority-aware ranking:** before truncation, a bounded adjustment favors maintained
  `_rules/`/`decisions/`/`procedures/`/`gotchas/` pages and `pinned`/`canonical` tags over
  episodic session evidence (without becoming absolute filters).

## Key persistence invariants

1. **Single writer.** Every mutation goes through the one writer actor thread (`WriteCmd`) —
   no concurrent writers, no `database is locked`.
2. **Content-addressed supersession.** sha256 equality short-circuits; changes create versions.
3. **Auto-improve optimistic concurrency.** Proposals snapshot the target's page-id/body-hash/
   updated-at at stage time; approval returns `Conflict` if the target changed since. **Pinned
   pages can never be rewritten** by auto-improve.
4. **Embedding consistency.** The denormalized `(provider, model, dim)` guards against mixing
   incompatible vectors.
