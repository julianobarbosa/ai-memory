# Development Guide — ai-memory

> Generated by BMAD `document-project` (deep scan, 2026-07-28). Canonical process rules live
> in [`../AGENTS.md`](../AGENTS.md) and [`../CONTRIBUTING.md`](../CONTRIBUTING.md); this is the
> quick operational summary.

## Prerequisites

- **Rust toolchain 1.95** (pinned in `rust-toolchain.toml`, `profile = minimal`, components
  `rustfmt` + `clippy`) — installed automatically by rustup when you build in-repo.
- **Edition 2024** (MSRV 1.95).
- A **C toolchain + CA certs** (SQLite is bundled via `rusqlite bundled`; libgit2 is vendored
  via `git2 vendored-libgit2` — no system SQLite/libgit2 needed).
- Optional: `cargo install cargo-deny cargo-audit` for the supply-chain gates.

## Build & run

```bash
cargo build --workspace                 # build everything
cargo build --release -p ai-memory-cli  # the shipped binary (release profile)

# Skip the ai-memory-web Tailwind asset build locally (recommended):
TAILWIND_SKIP=1 cargo build --workspace
```

`TAILWIND_SKIP=1` avoids the `ai-memory-web/build.rs` Tailwind CLI download/compile and uses
the vendored `tailwind.css`. CI, Docker, release, and AUR all set it.

Run the server locally:
```bash
cargo run -p ai-memory-cli -- serve --transport http --bind 127.0.0.1:49374 --enable-web
# or MCP over stdio:
cargo run -p ai-memory-cli -- serve --transport stdio
```

## Required gates before every PR

Enforced by CI (`.github/workflows/ci.yml`, `RUSTFLAGS=-D warnings`) and `bin/release`:

```bash
cargo fmt --all -- --check
TAILWIND_SKIP=1 cargo clippy --workspace --all-targets -- -D warnings
TAILWIND_SKIP=1 cargo test --workspace
cargo deny check          # license/source policy (rejects GPL/AGPL); --all-features in CI
cargo audit               # advisories (CI ignores a documented RUSTSEC allowlist)
```

Focused runs: `cargo test -p ai-memory-store` (or any single crate).

The out-of-tree companion is validated separately:
```bash
cargo test --manifest-path companions/ai-memory-importer/Cargo.toml
```

## CHANGELOG discipline (blocking)

**Every user-facing change must add a `CHANGELOG.md` `[Unreleased]` entry.** Reviewers treat a
missing entry as blocking. `bin/release` moves `[Unreleased]` → `[X.Y.Z]` at release time.

## Testing

- Standard Rust `cargo test` — no external runner.
- **Per-crate integration tests** in `crates/<crate>/tests/` (present for cli, mcp, store, wiki,
  hooks, web, llm, consolidate) plus in-module `#[cfg(test)]` units. Some files are heavily
  test-weighted (e.g. `ai-memory-web/src/mount.rs` is ~60% tests).
- **Root shell tests:** `tests/hooks/test_lib.sh`, `tests/e2e/handoff_smoke.sh` (the
  gitleaks-exempt canary path).
- CI matrix: Ubuntu + macOS gating; Windows non-gating (`continue-on-error`); a Docker smoke
  test builds the release binary and checks `--version`, bundled hooks, and `--help` command
  presence.

## Load-bearing invariants (don't break these)

1. **One SQLite writer actor** — all mutations serialize through it.
2. **Config read once at startup** — no scattered env reads in library crates; thread typed
   state in. (`hook`/`hook-drain`/`completions` short-circuit before config/tracing load.)
3. **Atomic file writes** (temp + rename) for every wiki page.
4. **CLI is always a thin HTTP client** — never touch SQLite/wiki files directly.
5. **Sanitize before persist** — enforced by the type system.
6. **Pinned pages are never auto-rewritten** by auto-improve.
7. **`unsafe_code = "forbid"`** workspace-wide; `missing_docs = "warn"`.

## Working on hooks

The ~21 vendored hook scripts under `hooks/<agent>/<event>.sh` are generated from a single
source of truth — regenerate with `bin/regen-hooks`, never hand-edit the outputs. Adding a
managed harness: [`managed-harness-contributions.md`](./managed-harness-contributions.md).
