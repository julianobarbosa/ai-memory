# Source Tree Analysis — ai-memory

> Generated by BMAD `document-project` (deep scan, 2026-07-28). Annotated map of the
> repository. Entry point is `crates/ai-memory-cli/src/main.rs` → the `ai-memory` binary.

## Top-level layout

```
ai-memory/
├── Cargo.toml               # Workspace root: 10 crates + evals, shared [workspace.package],
│                            #   release profile (lto=thin, codegen-units=1, strip), forbid unsafe
├── Cargo.lock               # Committed (this is an app, not a library)
├── rust-toolchain.toml      # Pins channel 1.95, components rustfmt + clippy
├── deny.toml                # cargo-deny: license allowlist (rejects GPL/AGPL), source locks
├── .gitleaks.toml           # Secret-scanning config (fail-closed; test-fixture allowlist)
│
├── crates/                  # ── The 10 shipped crates (see below) ──
├── evals/                   # Live A/B eval harness (ai-memory-eval; unpublished, not in CI)
├── companions/              # Optional out-of-workspace tools (own workspace + Cargo.lock)
│   └── ai-memory-importer/  #   Imports external memory corpora via POST /admin/write-page
│
├── hooks/                   # Vendored per-agent hook scripts (agents × events, ~21 .sh)
│                            #   regenerated by bin/regen-hooks; bundled into releases/Docker
├── docker/                  # Dockerfile (multi-stage) + compose files (dev, prod, TLS variants)
├── packaging/               # AUR PKGBUILDs, systemd units, sysusers, tmpfiles, env
├── scripts/                 # CI + manual ops scripts (check-native-packaging, install-hooks, ...)
├── bin/                     # Docker wrapper (bin/ai-memory), deploy, release, regen-hooks
├── tests/                   # Cross-cutting shell tests (hooks/, e2e/handoff_smoke.sh)
├── docs/                    # Documentation (hand-authored + this generated set)
├── .github/workflows/       # ci.yml, release.yml
│
├── README.md   AGENTS.md   CONTRIBUTING.md   CHANGELOG.md   SECURITY.md   CLAUDE.md   LICENSE
```

`AGENTS.md` is the canonical agent/process-rules file; root `CLAUDE.md` is a thin pointer to it.

## Entry points summary

| Entry point | Path | What it starts |
|---|---|---|
| `ai-memory` binary | `crates/ai-memory-cli/src/main.rs` | All ~50 subcommands |
| `ai-memory serve` | `crates/ai-memory-cli/src/commands/serve.rs` | The axum server (MCP+hooks+admin+web) or stdio MCP |
| `ai-memory-eval` | `evals/` | Live A/B eval of the consolidation prompt (dev only) |
| importer | `companions/ai-memory-importer/` | External-corpus import via server HTTP API |
