## What it is

**Long-term memory for AI coding agents.** Quit Claude Code mid-task, start OpenAI Codex
in the same directory, and continue without re-explaining the architecture, the failed
approaches, or the open questions. ai-memory captures sanitized lifecycle observations from
agent CLIs, consolidates them (optionally via an LLM) into a git-versioned markdown wiki, and
serves that wiki back to the next agent as bounded handoffs and searchable pages.

The wiki is **plain markdown in a git repo** — `grep`-able, openable in Obsidian, backed up
with `rsync`. No external vector database to babysit; semantic search (when enabled) rides on
SQLite (FTS5 + an embeddings blob table).

- **Upstream:** `github.com/akitaonrails/ai-memory` (Fabio Akita) · **License:** MIT · **Version:** 1.19.1
- **Default server port:** 49374 · **Zero-LLM by default** (FTS5 + rule-based summaries, $0)

## The crates at a glance

The workspace is a clean dependency stack: `core` (pure types) → `store` (SQLite) →
`wiki` (markdown+git) → `consolidate` (LLM pipeline); `llm` is consumed by the top crates;
`mcp`, `hooks`, `web`, `workstream` are the interface layers; `cli` is the only binary and
composes everything.

| Crate | Role | Binary? |
|---|---|---|
| `ai-memory-core` | Shared vocabulary: IDs, domain records (page/observation/session/handoff/user/workstream), errors, sanitizer | no |
| `ai-memory-store` | SQLite storage — single-writer actor, reader pool, 35 migrations, FTS5, embeddings, auto-improve, decay | no |
| `ai-memory-wiki` | Markdown-on-disk write authority — atomic writes, frontmatter, git, watcher, admission webhooks | no |
| `ai-memory-consolidate` | Karpathy-style LLM consolidation + maintenance jobs (bootstrap, lint, sweep, curator, embed, auto-improve) | no |
| `ai-memory-llm` | Provider-neutral LLM + embedding abstraction; native strict clients per provider | no |
| `ai-memory-mcp` | MCP server (`rmcp`) — 16 `memory_*` tools + `/admin` HTTP router + auth | no |
| `ai-memory-hooks` | Agent lifecycle-hook HTTP ingress → sanitize → store; session-page synthesis | no |
| `ai-memory-web` | Read-only wiki browser (`/web`) + `/api/v1` JSON API | no |
| `ai-memory-workstream` | Read-only native-harness adapters + managed-launch planning for `ai-memory run` | no |
| `ai-memory-cli` | **The `ai-memory` binary** — ~50 subcommands, thin HTTP client of the server | **yes** |
| `evals` (`ai-memory-eval`) | Live A/B eval harness for the consolidation prompt; never shipped, never in CI | yes (unpublished) |
